# Distractor Audit Statistics

## Overview

**Core Principle:** Objective, metrics-driven audit of all 831 generated distractors to identify problems (collisions, format issues, biases) and flag specific items for PASS 3 correction.

**Announce at start:** "Using distractor-audit-statistics to audit [COUNT] distractors for [POOL_NAME]"

This skill reads thresholds and validation criteria from FACTORY_REGISTRY_CORE. Modify registry → audit sensitivity adapts automatically.

---

## When to Use

This skill applies after **all 831 distractors have been generated by PASS 1**. Use it to:

- Detect collisions (distractors matching correct answers)
- Identify format inconsistencies
- Measure difficulty distribution
- Spot bias patterns (over-concentration, era clustering)
- Flag specific problematic questions for PASS 3
- Make GO/NO-GO decision before deployment

**Do NOT use this skill when:**
- Still in PASS 1 generation (incomplete pool)
- Fixing individual distractors (use distractor-optimizer instead)
- Defining rules (update FACTORY_REGISTRY instead)

**Prerequisites:**
- All 831 distractors generated and available
- 277 correct answers available for collision check
- FACTORY_REGISTRY_VALIDATIONS_QUALITY accessible
- Thresholds and metrics defined in registry

## The Process

### STEP 1: Load All Data

Prepare inputs for audit:

```
INPUT:
- 831 distractors (structured: question_id, type, difficulty, [D1, D2, D3])
- 277 correct answers (reference set)
- REGISTRY_VALIDATIONS_QUALITY (thresholds)
- REGISTRY_DEFINITIONS_CDM (context)
```

### STEP 2: Check Hard Collisions

**Purpose:** Find distractors that equal correct answers (most critical issue).

**Algorithm:**
```
FOR EACH distractor in 831:
  IF distractor == any of 277 correct answers:
    HARD_COLLISION_FOUND = true
    FLAG for PASS 3 (CRITICAL severity)
```

**Metric:**
```
HARD_COLLISIONS = count of matches
Success threshold: HARD_COLLISIONS = 0 (from REGISTRY_VALIDATIONS)
```

**Example:**
```
Q087 Distractor_1: "Ronaldo"
Correct answers include: "Ronaldo" (for question about Brazil's all-time scorer)
→ HARD_COLLISION detected
→ FLAG: Q087 distractor_1 must be replaced (type: hard collision)
```

---

### STEP 3: Check Soft Collisions

**Purpose:** Detect same entity appearing as both answer and distractor in different contexts.

**Algorithm for TYPE 1 & TYPE 5 (HIGH RISK):**
```
FOR EACH distractor:
  IF entity (e.g., player name) also appears as correct answer elsewhere:
    Retrieve both questions
    IF contexts are different (different criteria, same era):
      SOFT_COLLISION_SUSPECTED
      FLAG for review (MEDIUM severity)
    ELSE IF contexts are very similar:
      FLAG as SOFT_COLLISION (HIGH severity)
```

**Metric:**
```
SOFT_COLLISIONS = count of same-entity reuses
Threshold: <5% of total (from REGISTRY_VALIDATIONS)
```

**Example:**
```
Q042 Answer: "Eusebio" (Portuguese attacker, 1966)
Q156 Distractor_2: "Eusebio" (Portuguese player, different question context)
→ SOFT_COLLISION: Same player, different question
→ FLAG: Q156 distractor_2 (severity: MEDIUM, unless exact context match)
```

---

### STEP 4: Check Format Homogeneity

**Purpose:** Ensure within each question, all 4 options (1 answer + 3 distractors) have consistent format.

**Checks per question:**
```
correct_answer = "Eusebio"
distractor_1 = "Pauleta"
distractor_2 = "Figo"
distractor_3 = "Rui Costa"

Check CASE:
  ✓ All start with capital letter: Eusebio, Pauleta, Figo, Rui Costa

Check ACCENTS (if applicable):
  ✓ No inconsistency in FIFA spelling

Check TYPE_FORMAT (for TYPE 3, 2):
  If answer = "1998", all distractors = "1994", "2002", "2006" (not mixed with "édition 1998")
  ✓ Consistent

Check UNITS (for TYPE 2):
  If answer = "15" (no unit), all distractors = "12", "13", "17" (no units)
  ✓ Consistent
```

**Metric:**
```
QUESTIONS_WITH_CONSISTENT_FORMAT = count(questions where all 4 options match)
FORMAT_HOMOGENEITY = (QUESTIONS_WITH_CONSISTENT_FORMAT / 277) * 100
Threshold: ≥99% (from REGISTRY_VALIDATIONS)
```

**Flagging:**
```
If FORMAT_HOMOGENEITY < 99%:
  FOR EACH question with inconsistency:
    FLAG as FORMAT_ISSUE (severity: HIGH)
```

---

### STEP 5: Measure Difficulty Distribution

**Purpose:** Check if overall distribution matches target (N1: 25%, N2: 50%, N3: 25%).

**Calculation:**
```
N1_COUNT = count(distractors where difficulty_level == "N1")
N2_COUNT = count(distractors where difficulty_level == "N2")
N3_COUNT = count(distractors where difficulty_level == "N3")
TOTAL = 831

N1_PERCENT = (N1_COUNT / TOTAL) * 100
N2_PERCENT = (N2_COUNT / TOTAL) * 100
N3_PERCENT = (N3_COUNT / TOTAL) * 100

Example result:
- N1: 252 distractors (30.3%) [target 30%] ✓
- N2: 329 distractors (39.6%) [target 40%] ✓
- N3: 250 distractors (30.1%) [target 30%] ✓
```

**Thresholds (from REGISTRY_VALIDATIONS):**
```
Green (good):    Within ±5% of target (25-35%, 35-45%, 25-35%)
Yellow (caution): Within ±10% of target (20-40%, 30-50%, 20-40%)
Red (flag):      Outside ±10% of target
```

---

### STEP 6: Measure Type Distribution

**Purpose:** Check representation of each TYPE (1-5).

**Calculation:**
```
TYPE_1_COUNT = count(distractors from questions of TYPE_1)
TYPE_2_COUNT = count(distractors from questions of TYPE_2)
...
TYPE_5_COUNT = count(distractors from questions of TYPE_5)

Each TYPE's percent = (TYPE_X_COUNT / 831) * 100

Example result:
- TYPE 1 (Identification):   165 (31.2%)
- TYPE 2 (Numbers):           84 (31.4%)
- TYPE 3 (Years):            62 (32.1%)
- TYPE 4 (Location):         52 (29.5%)
- TYPE 5 (Correspondence):   70 (34.8%)
```

**Threshold:**
```
Success: All types > 10% (all represented)
Warning: Any type < 10% (under-represented)
```

---

### STEP 7: Analyze Reuse Patterns

**Purpose:** Detect if same distractors appear across multiple questions (should be <5%).

**Calculation:**
```
REUSE_DICT = {}
FOR EACH distractor:
  IF distractor in REUSE_DICT:
    REUSE_DICT[distractor] += 1
  ELSE:
    REUSE_DICT[distractor] = 1

REUSED_ITEMS = count(items where count > 1)
REUSE_RATE = (REUSED_ITEMS / 831) * 100

Example:
- "Ronaldo": 5 times (reused)
- "France": 3 times (reused)
- "Pelé": 2 times (reused)
- ... 200+ items used only once

REUSE_RATE = 3.2% [<5% ✓ Green]
```

**Threshold:**
```
Green:  <5%
Yellow: 5-10%
Red:    >10%
```

---

### STEP 8: Scan for Source Concentration

**Purpose:** Detect if a few players/countries dominate the distractor pool (bias).

**Calculation:**
```
SOURCE_COUNT = {}
FOR EACH distractor (focusing on TYPE 1, 5):
  entity = extract_entity_name(distractor)
  SOURCE_COUNT[entity] += 1

Sort by frequency, show top 20:
- Ronaldo: 14 times
- France: 12 times
- Pelé: 8 times
- ...

Concentration analysis:
- Top 3 sources: max 2% each (e.g., 16, 16, 16 uses out of 831)
- Top 10 sources: should be diverse
```

**Threshold (from REGISTRY_VALIDATIONS):**
```
Green:  No source > 2%
Yellow: Some sources 2-3%
Red:    Any source > 3%

Flagging:
If "Ronaldo" appears 25 times across distractors → FLAG (concentration risk)
```

---

### STEP 9: Detect Era Clustering

**Purpose:** Check if certain historical eras are over-represented in distractors.

**Analysis:**
```
FOR EACH question of TYPE 1 from ERA X:
  Count distractors also from ERA X
  If > 50% of distractors from question era → FLAG

Example:
- Q042 (1966 era Portuguese attacker question)
  - Distractors: Pauleta (1990s), Figo (1990s), Rui Costa (1990s)
  - 0% from 1966 era ✓ Good diversity
  
- Q087 (1950s era question)
  - Distractors: Fontaine (1950s), Zichon (1950s), Ademir (1950s)
  - 100% from 1950s era → FLAG (era clustering)
```

**Metric:**
```
QUESTIONS_WITH_ERA_CLUSTERING = count(questions > 50% distractors from same era)
Threshold: 0 clusters (ideal)
If any detected: FLAG for review
```

---

### STEP 10: Detect Nationality Bias

**Purpose:** Check if certain nationalities dominate distractor pool (especially TYPE 1, 5).

**Calculation:**
```
NATIONALITY_COUNT = {}
FOR EACH distractor of TYPE 1 or 5:
  nationality = extract_nationality(distractor)
  NATIONALITY_COUNT[nationality] += 1

Percentage distribution:
- Brazil: 15% of TYPE 1+5 distractors
- France: 12%
- Germany: 10%
- ... (should roughly match World Cup participation)

Expected: Balanced distribution reflecting CDM participant nations
```

**Threshold:**
```
Green:  Balanced (no nationality > 15%)
Yellow: Slight skew (one nationality 15-20%)
Red:    Strong bias (any nationality > 20%)

FLAG if:
- Brazilian players dominate (e.g., 25% of all distractors)
- European players under-represented
```

---

### STEP 11: Detect Type Imbalance

**Purpose:** Check if certain question TYPEs have drastically different difficulty distributions.

**Analysis:**
```
For each TYPE (1-5):
  TYPE_N1_PERCENT = (N1 distractors in TYPE / total TYPE distractors) * 100
  TYPE_N2_PERCENT = ...
  TYPE_N3_PERCENT = ...

Compare against global target (25/50/25):
- TYPE 1: N1=32%, N2=39%, N3=29% [±2-3% ✓ Good]
- TYPE 2: N1=25%, N2=45%, N3=30% [±5% acceptable]
- TYPE 3: N1=28%, N2=42%, N3=30% [within tolerance]
- TYPE 4: N1=20%, N2=50%, N3=30% [±10-15% FLAG]
- TYPE 5: N1=35%, N2=35%, N3=30% [±5% acceptable]

TYPE 4 shows imbalance: much easier than global average (too many N1)
→ FLAG: TYPE 4 difficulty distribution needs review
```

```
    "issue": "PLAUSIBILITY_LOW",
    "severity": "MEDIUM",
    "root_cause": "Distractor '47' (goals) is way too high, doesn't match answer context",
    "recommendation": "Use ±2 to ±3 range instead"
  },
  ...
]

Total flags: e.g., 23 questions need fixes out of 277
```

---

### STEP 13: Generate Decision Gate

**Determine GO/NO-GO:**

```
DECISION_LOGIC:
- If HARD_COLLISIONS > 0 → RED → CONDITIONAL_GO (must fix before deploy)
- If FORMAT_HOMOGENEITY < 95% → RED → CONDITIONAL_GO
- If DIFFICULTY_DIST outside ±15% → RED → CONDITIONAL_GO
- If CRITICAL_BIAS detected → RED → NO_GO (major rework needed)

- Else if SOFT_COLLISIONS > 10% → YELLOW → CONDITIONAL_GO
- Else if FORMAT_HOMOGENEITY 95-99% → YELLOW → CONDITIONAL_GO
- Else if DIFFICULTY_DIST within ±10% → YELLOW → CONDITIONAL_GO

- Else → GREEN → GO (ready for LAB)
```

## Red Flags: Audit Anti-Patterns

| Red Flag | What It Means | Action |
|----------|---|---|
| HARD_COLLISIONS > 0 | Critical: distractors matching correct answers | MUST fix in PASS 3 before any deployment |
| FORMAT_HOMOGENEITY < 95% | Inconsistent question formatting | Flag for PASS 3 correction |
| DIFFICULTY_DIST outside ±15% | Questions skewed too hard/easy | May indicate PASS 1 rule misapplication |
| Single source > 3% | Over-concentration risk (e.g., Ronaldo dominating) | Flag for PASS 3 diversity fix |
| Era clustering > 10 questions | Same era over-represented | Review PASS 1 generation for bias |
| One TYPE missing entirely | Under-representation | Indicates potential question pool issue |
| Reuse rate > 10% | Excessive distractors reused | Diversity degradation |
| All N1 (no N3) | No difficult questions | Check PASS 1 difficulty filtering |

## Success Criteria

**GO Decision requires:**
- HARD_COLLISIONS = 0
- FORMAT_HOMOGENEITY ≥ 99%
- DIFFICULTY_DIST within ±5%
- REUSE_RATE < 5%
- No critical biases

**CONDITIONAL_GO requires:**
- HARD_COLLISIONS ≤ few (fixable in PASS 3)
- FORMAT_HOMOGENEITY ≥ 95%
- DIFFICULTY_DIST within ±10%
- Actionable flags for PASS 3
- No structural issues

**NO_GO requires:**
- Major issues (rework needed)
- Return to PASS 1
- Revisit rules
