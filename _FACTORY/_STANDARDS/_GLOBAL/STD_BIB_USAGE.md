# STD_BIB_USAGE

STATUS: ACTIVE
MODE: MACHINE_FIRST
TYPE: RUNTIME_POLICY

---

# PURPOSE

Define:
- what the BIB is
- what the BIB is not
- how the FACTORY must use the BIB
- what the BIB may contain
- forbidden BIB usages

---

# DEFINITION

The BIB is:

> a searchable cultural matter reservoir.

The BIB provides:
- discovery candidates
- cultural fragments
- refs
- emotionally alive material
- socially reusable signals
- potential quiz matter

The BIB does NOT define:
- runtime rules
- generation logic
- validation logic
- procedural execution
- architectural constraints

---

# BIB_POSITION_IN_FACTORY

FACTORY:
- transforms
- filters
- validates
- structures
- generates

BIB:
- supplies raw cultural matter

Runtime hierarchy:

INTENT_PRELINE
↓
A2_PROCESS
↓
targeted_BIB_extraction
↓
A2_OUTPUT
↓
FACTORY_RUNTIME

The BIB never overrides:
- STD
- MDE
- runtime policies
- architecture rules

---

# ALLOWED_BIB_CONTENT

Allowed:
- cultural fragments
- expressions
- brands
- habits
- anecdotes
- local details
- socially alive situations
- emotionally memorable elements
- refs
- surprising facts
- hidden connections
- sounds and oralities
- everyday objects
- conversational signals

---

# FORBIDDEN_BIB_CONTENT

Forbidden:
- runtime rules
- validation logic
- hidden procedures
- execution instructions
- undocumented exceptions
- architecture overrides
- procedural logic
- QA blockers
- implicit standards
- historical runtime decisions

The BIB must never become:
- pseudo-STD
- pseudo-MDE
- hidden runtime layer

---

# EXTRACTION_POLICY

The BIB must be:
- searchable
- modular
- lightweight
- discovery-oriented
- emotionally useful
- non exhaustive

The FACTORY must:
- extract selectively
- filter aggressively
- reject low-energy material
- preserve anti-school-feeling

The FACTORY must never:
- load the entire BIB
- use the BIB as runtime memory
- treat the BIB as normative truth

---

# PRIORITY_FILTERS

BIB extraction priority:
- discovery potential
- shareability
- emotional texture
- ref potential
- intergenerational value
- conversational value
- screenshotability

Low priority:
- exhaustive history
- institutional data
- administrative content
- flat documentation

---

# REJECTION_CASES

Reject BIB material if:
- school feeling emerges
- emotional value is weak
- shareability is weak
- discovery density is low
- material is administratively written
- material is culturally flat
- content feels encyclopedic

---

# ANTI_PATTERNS

Forbidden anti-patterns:
- using BIB as hidden runtime memory
- embedding rules inside BIB
- storing procedural logic inside BIB
- mixing RETEX and cultural matter
- loading massive contextual dumps
- treating BIB as authoritative runtime layer

---

# RUNTIME_OBJECTIVE

The BIB exists to increase:
- curiosity
- discovery
- replayability
- emotional memorability
- social transmission

Without increasing:
- runtime entropy
- context cost
- school feeling
- documentary heaviness
